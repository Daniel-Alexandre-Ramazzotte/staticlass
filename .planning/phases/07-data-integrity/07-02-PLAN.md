<research_findings>
## Verified Findings

- `migrate_questoes.py` already disambiguates duplicate SQLite `original_id` values correctly, but still inserts chapters/topics with explicit IDs, omits `source`, and keeps a redundant pre-check before an `ON CONFLICT` alternative insert.
- `migrate_apostila.py` still deduplicates by `issue LIKE` and does not persist `original_id`.
- `migrate_source_enum.py` still has to normalize `NULL -> outro`, which proves the import pipeline is not yet self-contained on a fresh DB.
- Remaining BCB references are concentrated in `migrate_bcb.py` and `undo_bcb.py`.
- `undo_bcb.py` contains useful cleanup heuristics, but the BCB-branded entry point now conflicts with the phase context.

</research_findings>

<interfaces>
## Required Contracts For This Plan

1. `app/backend/statl/utils/migration_utils.py`

Required helpers:
- `get_engine()`
- `content_hash(issue: str, correct_answer: str, prefix: str = "") -> str`
- `get_or_create_chapter(conn, *, name: str, number: int) -> int`
- `get_or_create_topic(conn, *, name: str, chapter_id: int) -> int`
- `upsert_question(conn, payload: dict) -> tuple[int, bool]`
- `upsert_alternatives(conn, question_id: int, alternatives: list[dict]) -> int`

Rules:
- no helper may depend on `migrate_bcb.py`
- hash output must fit inside `questions.original_id`
- helpers must be safe to call repeatedly

2. `migrate_apostila.py`

Required identity contract:

```text
original_id = "apostila__" + sha256(issue.strip() + "|" + correct_answer.strip().upper())[:32]
```

This keeps the ID deterministic, stable across reorderings, and safely within the current 50-character column limit.

3. Supported CLI surface after this plan

Supported:
- `python -m statl.migrate_questoes`
- `python -m statl.migrate_apostila`
- optional neutral cleanup path such as `python -m statl.cleanup_legacy_question_bank [--dry-run]`

Not supported:
- `python -m statl.migrate_bcb`
- `python -m statl.undo_bcb`
